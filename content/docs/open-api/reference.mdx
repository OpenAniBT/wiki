成功响应按端点解析：目录、查询、/me 和同步状态使用 `data`；发布、whoami、删除使用 `result`；标题匹配直接返回 `version`、`decision`、`candidates`。番剧预览使用顶层 `previewUrl`，不能按普通发布回执读取。

标题匹配的 `candidates[].matchScore` 只能比较大小，不是百分比。`evidenceSummary.matchClass` 为 exact、structured_exact、compact、base 时分别为 100、95、90、80；只由召回（`strict_recall`、`fuzzy_recall`）找到的候选为 1–70，有拼写差异或忽略了一个词时更低；只因系列补全加入的候选为 0。召回候选同分时由 `textMatch` 区分先后，它同样只能比较大小。

应用 JSON 错误包含 `ok: false` 和 `error.code`、`error.message`、`error.requestId`；`reason`、`retryable`、`retryAfterMs`、`details` 为可选字段。缺少 `retryable` 不表示可以重试。公开 RSS 的错误通常是纯文本；Torznab 协议错误是 XML，HTTP 状态仍可能为 200；边缘拦截还可能返回 HTML。先检查 HTTP 状态与 Content-Type，再解析正文。

发布前用 GET 同一路径核验 `groupSlug` 和 `scopes`。发布成功回执只保证 `releaseId`、`revision`，可能含 `torrentObjectId`，不包含字幕组身份或 `fileSize`。资源 ID 使用端点要求的 `rel_*` 或 `orel_*`；字幕组通常用 `slug`，但其他类 RSS 的 `groupId` 使用组织 ID。

## 发布重试与删除后重新发布

普通发布的同一次请求建议使用 `Idempotency-Key`。同一 API Key、同一发布端点重试相同内容时，保留原值；该值去除首尾空白后须为 1–256 字符。未提供或为空时按新命令处理，不能依赖命令回放。超过 256 字符时返回 `422 VALIDATION_ERROR`，`error.details` 为 `{ "header": "Idempotency-Key", "maxLength": 256 }`；服务端不读取请求体，也不发布。跨站浏览器预检目前不允许该请求头；需要此保证的客户端应从服务端调用。

成功命令的重试返回原 `releaseId` 与 `revision`，不会重新发布。即使原资源已经删除，同一个命令仍返回旧回执，不会恢复资源；删除后有意使用同一种子重新发布，应使用新的 `Idempotency-Key`。

从首次受理开始，`Idempotency-Key` 绑定完整请求。切换发布与预览，或更改资源内容、Nyaa 选项、显式发布时间、上传文件时，应使用新键。上传完成或已有回执不能绕过已保存的绑定；同键改参返回 `409 CONFLICT`。

升级前已上传但尚未完成的请求，若缺少完整绑定，会返回 `409 CONFLICT`，`error.reason` 为 `legacy_request_binding_missing`。此时请使用新键重新提交完整请求。已完成的旧请求仍按原回执重放。

本组在同一番剧下已经有集数键、版本、字幕类型、分辨率、语言都相同，且种子相同的资源时，再次发布返回 `409 CONFLICT`，`error.reason` 为 `RELEASE_VERSION_EXISTS`。这表示这份种子已经以同一版本发布过，换新键重试也不会成功。

一个已存储的种子只能用于一条资源。JSON 请求的 `torrentStorageId` 指向的种子已被另一条番剧资源、其他类资源或他人未过期的预览使用时，发布和预览都返回 `409 CONFLICT`，`error.reason` 为 `TORRENT_IN_USE`，不写入任何内容；请改用 multipart 上传种子文件。同一发布者重发内容相同的番剧资源时仍返回已有资源；自己预览过的种子可以直接正式发布，正式发布后这个种子的预览随即失效。

字幕组状态不是「活跃」（为「不活跃」或「已停用」），或 Key 在请求处理期间被撤销时，发布返回 `403 FORBIDDEN`。

成员离开或被移出字幕组时，他在该组的 API Key 同时撤销，之后使用这些 Key 的请求返回 `401`；即使再次加入字幕组，这些 Key 也不会恢复，需要新建。修改成员角色不影响 Key。

请求里的磁力链接须含 v1 infohash：`xt=urn:btih:` 后接 40 位十六进制或 32 位 base32。`xt` 键不区分大小写，`XT=urn:btih:…` 同样接受；同时带 `urn:btmh` 的混合磁链，`urn:btmh` 写在 `urn:btih` 前面也接受。

以下请求返回 `422 VALIDATION_ERROR`，`error.message` 说明违反的规则：

- 集数键为空；
- `episode` 与 `episodeKey` 不一致；
- 磁力链接没有 `xt=urn:btih`，或其中不是有效的 v1 infohash，或种子的磁力链接里没有 infohash；
- 没有种子，又缺少大于 0 的文件大小或 infohash；
- `torrentStorageId` 不存在或不属于本组；
- 字段超过长度上限，`error.details.fieldErrors` 列出超限的字段。

这些请求原样重试或换新键重试都不会成功。

请求头 `Content-Length` 只能由数字组成。含其他字符时（如 `1e3`、`1.5`、`-1`），发布返回 `400 INVALID_BODY`，`error.message` 为 `Invalid Content-Length`，不读取请求体，也不发布；有些写法在到达应用之前就会被拒绝，这时同样是 `400`，但正文不一定是 JSON。请求体没有读完（例如上传中途断开）时返回 `400 INVALID_BODY`，`error.message` 为 `Request body could not be read`，不再返回 `500 UPLOAD_FAILED`，也不发布。请求体超过上限时仍返回 `413 SIZE_EXCEEDED`，上限见[限流与参数上限](/docs/open-api/limits)。

数字集数键按规范写法保存：去掉前导零，小数再去掉末尾的零。`05.5` 和 `5.50` 都存为 `5.5`，`01` 存为 `1`，`01-13` 存为 `1-13`。

番剧发布未传 `resolution` 时，只从标题里写明分辨率的片段识别：`1080p`、`1080P`、`1080i`，`1920x1080`、`3840x2160` 这样的宽 × 高，以及独立成词的 `4K`。`2160p` 与 `3840x2160` 识别为 `2160p`，写明 `4K` 时才是 `4K`。集数、不带 `p` 或 `i` 的裸数字（如 `1080`、`720`、`2160`）、校验码里的数字，以及粘在单词里的 `4K`（如 `Show4Kids`）都不算分辨率：`[Group] One Piece - 1080 [720p].mkv` 识别为 `720p`。标题里识别不出时，按同样的规则读取种子内部名，仍识别不出时为 `1080p`。

发布端点的 POST 与 GET（whoami）在校验 Key 之前就按来源计数，Key 无效的请求同样计数；超出额度时直接返回 `429`，不会校验 Key。whoami 单独计数，不占用发布的额度。额度见[限流与参数上限](/docs/open-api/limits)。

收到 `429 RATE_LIMIT_EXCEEDED` 时，按 `Retry-After` 的秒数等待。发布暂时繁忙、限流服务暂时无法计数或上传结果待确认时可返回 `503 SERVICE_UNAVAILABLE`；限流服务无法计数时 `Retry-After` 固定为 15。`503` 带 `Retry-After` 时按它等待，再用原 key 重试同一请求；没有该头时先核查现有发布并保留 `error.requestId`。失败或连接中断不证明未写入，不要立即批量重试，也不要为一次不确定的结果反复换新 key。

## 删除被拒绝时的响应

`DELETE /api/releases/{releaseId}` 在资源不存在、属于其他字幕组，或普通成员的 Key 删除同组其他成员发布的资源时，返回 `404 NOT_FOUND`，`error.message` 为 `Release not found`；这几种情况的响应完全相同。普通成员的 Key 只能删除自己发布的资源，owner/admin 的 Key 可以删除本组所有资源。

字幕组状态不是「活跃」（为「不活跃」或「已停用」），或 Key 在请求处理期间被撤销时，删除返回 `403 FORBIDDEN`，资源不会被删除。成员离开或被移出字幕组后，他在该组的 Key 已撤销，删除请求返回 `401`。
