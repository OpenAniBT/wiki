The production base URL is https://anibt.net. Group API keys, personal RSS tokens, and login sessions serve different endpoints and are not interchangeable. Parse each endpoint’s envelope, nullable fields, and error format as documented.

The machine-readable contract is [/openapi.yaml](/openapi.yaml). Endpoint pages show request fields and response examples. Title matching is anonymous unless groupId is supplied, which requires a session and group membership.

## Anime queries and ratings

`scope.kind` on `/api/seasons/anime` distinguishes season browsing, title search, and exact ID lookup. A global title search returns `requestedSeason: null`; each anime carries its own season. Premiere dates remain separate from season classification. `premiere.precision` is `day`, `month`, `season`, or `year`; a coarse date uses the start of that period.

Season browsing returns at most 200 items; title search returns at most 50. `total` counts the returned items and `truncated=true` means more results exist. Use `/api/animes/search` for pagination; see [Anime search](#anime-search). `rating` uses a 0–10 scale and defaults to `5.0` when no valid rating is available; `averageScore` uses 0–100 and defaults to `50`. Existing ani-rss can sort these scores. Older versions ignore truncation indicators and still display at most 50 search results.

Default ratings update automatically when a later sync obtains a valid source rating. Manually locked ratings remain unchanged. Metadata follows the existing sync frequency; page views and RSS subscriptions do not refresh upstream records individually.

## Anime search

`/api/animes/search`, `/search`, `/api/bgm/search`, and the `query` of `/api/seasons/anime` share one title search. It compares every title and alias of an anime.

Before comparing, case and full-width forms are normalized, katakana folds to hiragana, and Traditional and Japanese shinjitai characters fold to Simplified. Spaces and punctuation are then ignored. `ふりーれん` finds katakana titles, and `進擊` finds Simplified titles.

Matches are ranked by tier, then by popularity (descending), then by anime ID (ascending):

1. **Exact**: a title or alias equals the query.
2. **Prefix**: a title or alias starts with the query.
3. **Substring**: a title or alias contains the query.
4. **Multi-word**: every term hits some title or alias of the same anime, in any order and possibly across different titles. Used only for 2–16 terms; with more terms this tier is skipped, without an error.
5. **Ordered characters**: 2–4 Chinese or Japanese characters appear in order in one title or alias, not necessarily next to each other. `进巨` finds 进击的巨人.
6. **Similarity**: titles or aliases spelled similarly.

`/api/animes/search`, `/search`, and `/api/bgm/search` return results in this order. `/api/seasons/anime` uses it only to choose up to 50 anime; its response is still grouped by weekday and ordered by air time and title within each group.

Limits:

- Spelling tolerance comes only from similarity. Long titles tolerate small differences, such as `kimetu no yaiba`; a transposition in a short word, such as `freiren`, may find nothing.
- All punctuation separates terms, so `Re:Zero` and `Re Zero` are the same query. A year has no special rule; it matches like any other term.
- A query of 1–2 characters uses no substring or similarity matching. Whether it matches a given title or alias depends on how the two relate:
  - A query equal to the whole title or alias, ignoring spaces and punctuation, always matches.
  - Latin letters and digits must be a whole word or the start of a word in it. `rk` and `or` don't match letters inside a word.
  - Chinese and Japanese must be a single character in it or two adjacent characters. Punctuation in the query is removed first, so `ス・ダ` matches a title or alias with those two kana next to each other, not one that writes them apart with punctuation (unless the whole title or alias is just those two kana). Two characters with no space or punctuation between them can also match by ordered characters, as above.
  - A mix of Chinese or Japanese with letters or digits, such as `人0`, matches only an identical whole fragment: a piece set off by spaces or punctuation.
- A query that folds to nothing, such as `☆★`, returns an empty last page.

### Anime search pagination

`/api/animes/search` accepts `q`, `format`, `status`, `seasonYear`, `limit` (default 24, range 1–50), and `cursor`. It returns `page`, `isDone`, and `continueCursor` directly, without an `ok` or `data` wrapper.

<Callout type="warn">
  `continueCursor` is an opaque token and an empty string on the last page. Pass it back unchanged; don't parse it or build your own.
</Callout>

These `cursor` values return 422 `VALIDATION_ERROR`:

- A self-built `ts_page:N` or any other malformed value.
- A value not issued for the same query, filters, and search policy.
- A value sent with an empty query.

Cursors issued before the October 31, 2026 update no longer work. On 422, drop `cursor` and start again from the first page.

## Release search

`/magnets?q`, an anime page's release search, other-release categories, `/rss/magnets.xml?q=`, `/rss/other/<category>.xml?q=`, and `/torznab/api?q=` follow these rules. Every term must hit, with no typo tolerance, no prefix completion, and no dropped terms (for the `/magnets?q` exception, see [Relaxed search](#relaxed-search-on-magnets)):

- An anime release is compared on its own title and spec (episode label, resolution, format, subtitle type, language) and on every title and alias of its anime. Different terms can hit different places, so any alias of the anime finds releases titled only in another language.
- An other-category release is compared only on its own title and category.
- Latin letters and digits must be whole words: `HEV` doesn't find `HEVC`, `1080` doesn't find `1080p`, and `LoliHous` doesn't find `LoliHouse`.
- Chinese and Japanese match as contiguous characters and need not be a whole word: `鬼灭` finds releases of 鬼灭之刃.
- Letters and digits ignore case and width on every surface, and kana and Traditional/Simplified characters fold as in anime search.

Results are listed only by the chosen sort, newest first by default, with no relevance ranking. Torznab always sorts by publish time, newest first.

Only when the strict first page is empty does one split/join fallback run: `Loli Hose` finds `LoliHose`, `rezero` finds `Re:ZERO`, and `Re:Zero` finds `ReZero`. The fallback relaxes only the boundary between adjacent words, never exclusions, and later pages keep the first page's matching mode.

### Relaxed search on `/magnets`

For anime releases, when the first page of `/magnets?q` is still empty after strict matching and the split/join fallback above, the search runs once more with relaxed matching, and the page says the results are relaxed. The sort stays the same and no term is dropped. The steps run in order, and the first with results wins:

1. **Word prefix:** the last part of a term may be just the start of a word if it has no digit and at least 3 characters: `HEV` finds `HEVC`, and `LoliHous` finds `LoliHouse`. A part with a digit isn't completed, so `1080` still doesn't find `1080p`.
2. **Anime title similarity:** a single spelling difference in an anime title may match: `kimetu no yaiba` finds releases of Kimetsu no Yaiba. The terms with no digit must total at least 6 characters (4 if all Chinese or Japanese); a term with a digit doesn't count, and a shorter query skips this step. Terms with a digit, terms of 1–3 characters, and multi-part terms such as quoted phrases must still hit strictly: `kimetu no yaiba 1080p` lists only 1080p releases, `kimetsu no yaiba 2160p` stays empty when no 2160p release exists, and `"kimetu no yaiba"` in quotes is empty too. A release's own text, such as a group name, gets no such tolerance.

If the relaxed read fails on the first page, the answer is the strict search's empty result, not an error; if it fails while paging through relaxed results, the answer is a 503 like any other search. An anime page's release search, other-release categories, RSS, and Torznab always match strictly, so a term that only finds results on `/magnets` through relaxed matching may be empty in RSS.

### Punctuation, quotes, and exclusions

- A term with no digit splits at its punctuation, and each part matches on its own: `Nix-Raws`, `Re:Zero`, and `鬼灭/第二季` are two terms each, so one can hit an anime alias and the other a release title.
- A term with a digit and several parts is one phrase: the parts of `HEVC-10bit`, `x264-AAC`, and `第2期` must be adjacent and in order within one text (the release's own title and spec, or one title or alias of its anime). `HEVC-10bit` doesn't find `10bit x264 HEVC`, and `第2` doesn't match `第20期`.
- A complete quoted phrase standing as its own term is one phrase and may contain spaces: `"25 1080p"`. A quote attached to other characters, or left unclosed, is ignored and its words are ordinary terms.
- `-word` excludes, and reads only the release's own title and spec, never anime aliases. `-web-dl` needs `web` and `dl` adjacent and in order, so it doesn't exclude `WebDL` written as one word. `-"25 1080p"` excludes that phrase.
- A `-` with whitespace on both sides is a separator: `Title - 25` searches for `25`, and `Title -25` excludes `25`.
- Use the half-width `-` and `"` for exclusions and quoted phrases. Full-width operators can behave differently between surfaces and should not be relied on.

### Term limits and empty queries

A query carries at most 16 positive terms and 8 exclusions. A quoted phrase or a word with a digit counts as 1, `a/b/c` counts as 3, separators and symbol-only tokens don't count, and each exclusion counts as 1. Past the limit, each surface answers:

A query with no positive term (`-`, `☆`, or only exclusions such as `-25`) is not an error. Pages return an empty page, RSS returns a valid empty channel, and Torznab returns an empty list with `total` 0. Such a query issues no cursor, and a cursor sent with it is treated as invalid.

When an empty `q=` is sent, `/magnets` lists all releases, Torznab lists the latest releases, and RSS returns 400.

### Release search pagination

- A stale `/magnets` page link returns to the first page of the current view, including search page links saved before the October 31, 2026 update.
- RSS has no pagination. Torznab uses a bounded `offset`.

## When search is unavailable

When a search times out or can't complete, a surface never returns partial results or substitutes an empty result. The one exception is a failed relaxed read on the first page of `/magnets?q`: the strict search has already found nothing, and that empty result stands.

## Airing status

Automatic completion requires exact premiere and end dates, plus another source verification confirming the end after that entire day has elapsed. Dates are compared in Japan time. A year, month, season, or anime format alone cannot establish completion.

Automatic status is recalculated when synchronization receives a corrected airing plan. Manually locked statuses and explicit hiatus or cancellation take priority. Titles without sufficient evidence have an unknown status; unsupported historical statuses and planned end dates are not proof of completion.

The homepage shows only the latest episode of each anime on a given day. Genuine releases on different days remain separate.
