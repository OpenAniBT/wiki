AniBT supports seamless "publish once, synchronize everywhere" capabilities. Fansub groups only need to submit a release once on AniBT, and our background system automatically synchronizes the torrent file, title, category, and release notes to major external BT distribution sites.

<Callout type="info">
  Site sync is exclusively available to fansub groups. Complete [Fansub Onboarding](/en/docs/apply) before configuring. Credentials are encrypted and configured per site in your console at `/groups/<slug>/sync`.
</Callout>

## Sync Workflow & Status Tracking

Once a release is accepted on AniBT, asynchronous tasks are queued for each enabled external destination:

<Steps>
  <Step>
    ### Save and Test Credentials
    Visit `/groups/<slug>/sync` in your fansub console and enter credentials for your chosen sites. Always click "Test Connection" to ensure valid credentials before publishing.
  </Step>

  <Step>
    ### Automated Dispatch on Release
    When submitting anime or other releases, AniBT automatically schedules uploads to all enabled external sites. Each upload is processed independently in background queues; temporary connection dips on one site do not affect others.
  </Step>

  <Step>
    ### Inspect Status & Retry
    Click the "Site Sync" status badge on any release card in your console to view real-time sync progress, external URLs, and error diagnostics. When a site fails, any group member can click "Retry sync" to resubmit that failed attempt. A retry is refused while the site already has a queued or running job, so repeated clicks do not submit twice.

    An attempt whose outcome is uncertain (ambiguous) may already be on the external site, so it offers no retry and still shows as failed. Check the external site first. To submit again, a group owner, group admin or site administrator uses "Resend". Resending submits the release again and may create a duplicate post.
  </Step>
</Steps>

Sync logs refresh about every 5 seconds while tasks are queued or running, and check about every 30 seconds while idle. Tasks started from another page or device may appear at the next check; this does not delay their execution.

## Standard Sync States

When inspecting progress in the console or via the [Sync Status API](/en/docs/open-api/releases-sync-status), each platform returns one of the following states:

<TypeTable
  type={{
    'not_started': { type: 'Status', description: 'Site sync is disabled in settings or unchecked for this release.' },
    'pending': { type: 'Status', description: 'Queued or actively uploading to the destination site.' },
    'success': { type: 'Status', description: 'Successfully published externally; response includes the external release URL.' },
    'failed': { type: 'Status', description: 'Upload failed due to bad credentials, invalid category, or external downtime.' },
    'ambiguous': { type: 'Status', description: 'No clear confirmation came back from the external site, so the release may already be there. The system does not retry it and the console offers no retry; after checking, a group owner, group admin or site administrator can resend.' },
  }}
/>

<Callout type="warn">
  Anime claims (binding a seasonal anime to your group and custom title templates) are managed in `/groups/<slug>/claims`, separate from site sync credentials.
</Callout>
